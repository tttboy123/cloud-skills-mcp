ACR data-plane calls first obtain `https://containerregistry.azure.net/.default`, then perform the AAD-to-refresh and refresh-to-scoped-access exchanges inside the server. The current Microsoft permission constants cover registry `catalog`/`deleted_catalog` and repository `pull`, `push`, `delete`, `metadata_read`, `metadata_write`, `deleted_read`, and `deleted_restore`; the server binds the least request-appropriate documented combination to the exact URL and method. Cross-repository blob mounts add only the exact source-repository pull scope documented by the repeated `scope` form field. These sources are protocol evidence only: the runtime never invokes Azure CLI. Provider-owned GET/HEAD redirects drop Authorization, and neither token responses nor signed Location values enter MCP output.

The adapter uses only EnvironmentCredential, WorkloadIdentityCredential, and ManagedIdentityCredential. Azure CLI credentials are intentionally excluded. Azure OpenAI Realtime obtains the documented `https://ai.azure.com/.default` token internally, sends it only in the WSS Authorization header, validates JSON event framing and terminal events, and never accepts the API-key alternative. The current Realtime contract publishes only the single-label public host `<resource>.openai.azure.com`; its Global deployment regions are public Azure. The Azure Government model page states that its list includes all Azure OpenAI models offered there and lists no Realtime model, while no Azure China Foundry Realtime endpoint contract is published. Sovereign guesses and nested/lookalike hosts therefore fail closed. Voice Live uses the same bounded event engine on exact single-label public Foundry or legacy Speech WSS endpoints and selects `https://ai.azure.com/.default` or `https://cognitiveservices.azure.com/.default` from that endpoint. The current Azure Speech sovereign-cloud page explicitly marks Voice Live unsupported in both Azure Government and China, so sovereign guesses fail before token resolution. The reserved `privatelink` DNS-zone label is rejected as a direct resource host; normal public resource hostnames remain usable when Azure Private Link DNS resolves them privately inside the operator VNet. Model sessions remain read-only; configured Agent sessions require mutation approval, and credential-bearing avatar/ICE events fail before output. Azure Web PubSub obtains `https://webpubsub.azure.com/.default`, calls the fixed Generate Client Token API internally, and sends the five-minute client token only in the validated WSS Authorization header. Both standard and MQTT clients follow Microsoft's Private Endpoint rule: keep the public resource URL and let VNet DNS resolve it privately; direct `privatelink` URLs fail before token resolution. It supports standard and reliable JSON/Protobuf subprotocols plus finite MQTT 3.1.1/5.0 read or bidirectional client profiles whose token requests include `clientType=MQTT`. Protobuf wire fields, Any/binary data, streaming messages, uint64 acknowledgement and reliable recovery are handled inside the server; MQTT publish, QoS 2, persistent sessions, Last Will, MQTT 5 message/session properties, subscription identifiers, negotiated flow-control limits, and server disconnect are implemented. Azure SignalR Service serverless JSON-hub WSS requests `https://signalr.azure.com/.default`, calls the fixed `POST /api/hubs/{hub}/:generateToken?api-version=2022-11-01` with bounded `minutesToExpire` and optional `userId`, and dials the exact public `<resource>.service.signalr.net/client/?hub=<hub>` URL with the client token only in the internal `access_token` query parameter. The hub name follows the swagger contract (alphabetic start, alphanumeric or underscore only); `Subscribe` is a read-only listener that auto-replies void Completion frames, and `Invoke` is mutation-only with correlated StreamItem/Completion terminal state. The JSON Hub Protocol handshake, `0x1E` framing, Ping/Close handling, and completion error rules come from the official Hub Protocol specification; unsupported message types and lookalike/sovereign hosts fail before token resolution. Event Grid Namespace MQTT v5 separately requests `https://eventgrid.azure.net/.default` and places the JWT only in `OAUTH2-JWT` CONNECT/AUTH packets. Service Bus and Event Hubs accept the exact public, US Government, or China `$servicebus/websocket` endpoint with `amqp`, while the official SDK performs SASL/CBS and AMQP 1.0 state internally using the respective fixed Entra scope. Operators must configure Azure Identity for the matching authority. Direct private-DNS-zone names, custom/lookalike domains, and retired Germany endpoints are rejected. Lock tokens, session locks, CBS claims, client/recovery tokens, Entra tokens, and SignalR client tokens are never returned. Client-certificate, SAS/connection-string, and password authentication remain intentionally outside the operator-IAM-only MCP credential boundary.
